# Native file access

Native file access reads and writes DB2 for i files directly, using dedicated RPG operation codes (`chain`, `read`, `write`, ...). It is the classic alternative to embedded SQL, covered in the next chapter.


## Declaring files : dcl-f

A file is declared with `dcl-f`, followed by the file name. `usage` controls which operations are allowed, and defaults depend on the kind of file.

```
   dcl-f items;                                     // default usage is *input
   dcl-f customers usage(*update : *output);        // *update implies *input
   dcl-f orders    usage(*delete);                  // *delete implies *input *update

   dcl-f ord01d   workstn;                          // default usage *input and *output
   
   dcl-f ordlist  printer;                          // default usage *output
```

- Without `usage`, a database file defaults to `*input` only, a display file (`workstn`) defaults to both `*input` and `*output`, a printer file defaults to `*output`.
- `*update` and `*delete` each imply the access they need to do their job: you cannot update or delete a record without first being able to read (`*input`) it.

### keyed

By default, a file is accessed in arrival sequence: records come back in the order they physically sit in the file. `keyed` switches a file to key access instead, records can then be retrieved directly by their key value.

```
   dcl-f customers keyed;
```

- `keyed` is required before `chain`, `setll`, `setgt`, `reade` or `readpe` can be used with an actual key value.
- Without `keyed`, a file can still be read sequentially with `read`, in the order the records physically appear.

### alias, extdesc and extfile

```
   dcl-f orders keyed alias;
```

- `alias` lets long, SQL-style field names be used in RPG, instead of the 10-character names a DDS-described file is limited to.

```
   dcl-f yearEndReport printer
      extdesc('YERPT')
      extfile(*extdesc);
```

- `extdesc('...')` tells the **compiler** which file to get the record format layout from, when it is not the same as the name on `dcl-f`.
- `extfile('...')` tells the **program**, at run time, which actual object to open, `*extdesc` reuses whatever was specified on `extdesc`.
- Together they let the same source be compiled once against one file, while opening a different (but identically laid out) file at run time, without needing an override (`OVRDBF`).

### Long field names

DDS-described files are limited to 10-character field names, `alias` (above) is the usual workaround. Files created through SQL (`CREATE TABLE`), on the other hand, can already have field names up to 128 characters, RPG can use those names directly without needing `alias`.

### Renaming a record format

RPG requires every record format used in a program to have a unique name. `rename` gives an externally described record format a different name inside the program, typically needed when two files happen to share the same record format name.

```
   dcl-f orders keyed rename(orderRec : orderRecIn);
```


## Reading records

### Chain and %found()

`chain` retrieves one record directly by key (or by relative record number), without reading everything before it. `%found(file)` tells whether a matching record was found.

```
   chain custNr customers;

   if %found(customers);
      dsply custName;
   endif;
```

### Composite keys

When a key consists of more than one field, list them between parentheses, separated by colons. This replaces the `klist`/`kfld` construct from fixed-format RPG, which does not exist in free format.

```
   chain (custNr : orderNr) orders;

   if %found(orders);
      dsply orderDate;
   endif;
```

### Setll, Setgt, *start and *end

`setll` and `setgt` position the file at a key, without reading a record, typically used before a sequential loop. `setll` positions at the first record with a matching (or next higher) key, `setgt` positions just after it, skipping past any records with that exact key.

```
   setll custNr orders;             // position at the first order for custNr

   setgt custNr orders;             // position just after the last order for custNr
```

The special values `*start` and `*end` position at the very beginning, resp. end of a file, without needing a key value. This is the one form of `setll` that also works on a file that is not `keyed`, it is the usual way to (re)position at the beginning of a file accessed in arrival sequence, before reading it sequentially with `read`.

```
   setll *start orders;

   read orders;
   dow not %eof(orders);
      dsply orderDate;
      read orders;
   enddo;
```

### Read, Reade, Readpe and %eof()

`read` reads the next record in the file, in key or arrival sequence. `%eof(file)` becomes true once there are no more records.

```
   read orders;

   dow not %eof(orders);
      dsply orderDate;
      read orders;
   enddo;
```

`reade` reads the next record only as long as it still matches a given key, `readpe` does the same but backwards (read prior equal). Both are typically combined with `setll`/`setgt` to loop through just one key group.

```
   setll custNr orders;
   reade custNr orders;

   dow not %eof(orders);
      dsply orderDate;
      reade custNr orders;
   enddo;
```


## Write, Update and Delete

```
   dcl-ds orderRec extname('ORDERS') qualified;
   end-ds;

   orderRec.custNr = 1001;
   orderRec.orderDate = %date();
   write orders orderRec;               // add a new record

   chain 1001 orders;
   orderRec.status = 'SHIPPED';
   update orders orderRec;              // change the record just read

   delete orders;                       // remove the record just read
```

- `write` adds a new record.
- `update` changes the record that was last read (with `chain`, `read`, `reade`, ...).
- `delete` removes the record that was last read, or (like `chain`) a record identified directly by key.


## DSPF

A simple display file example, without subfiles, just to show the mechanics.

```
   dcl-f ord01d workstn;               // default usage *input and *output

   dow *in03 = *off;                   // *in03 is on when F3 (Exit) was pressed
      exfmt ord01dfmt;                 // write the format, then wait for the user's response

      if *in03 = *off;
         // ... process the fields the user entered ...
      endif;
   enddo;

   *inlr = *on;
```

- `exfmt` writes a record format to the screen and immediately reads the user's response back, the usual way to show one interactive screen.
- Which indicator reflects which function key depends on how the display file's DDS defines it, `*in03` for F3 (Exit) is a very common convention.


## PRTF

A printer file does not need its own DDS source, `qprint`, a printer file IBM i already provides, can be used directly.

```
   dcl-f qprint printer(132);          // program-described, 132 characters per line

   dcl-ds printLine len(132);
      text char(50);
   end-ds;

   printLine.text = 'Hello world';

   write qprint printLine;

   *inlr = *on;
```

- `printer(132)` makes this a program-described printer file with 132 characters per line, no external record format is looked up.
- This will be used in the exercises, as a quick way to produce printed output without first having to design a DDS printer file.
