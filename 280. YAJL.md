# YAJL

## What is YAJL ?

YAJL = Yet Another JSON Library

YAJL is a very fast tool for generating and parsing JSON.

We use YAJL mainly for generating JSON’s, because there are already (newer) solutions for parsing JSON like JSON_TABLE in SQL and DATA INTO in RPG.

YAJL was originally written in C, but Scott Klement & David Rosso ported YAJL to IBM i. 
YAJL is now available for downloading at http://www.scottklement.com/YAJL


## JSON

Example of a JSON

```
{
    "success": true,
    "errmsg": "",
    "list": [
        {
            "invoice": "70689",
            "date": "03/01/2014",
            "name": "SCOTT KLEMENT",
            "amount": 14.80,
            "weight": 0.5,
        },
        { another invoice },
        { another invoice },
        ...etc...
    ]
}
```

## Service program

The YAJL installation comes with a binding directory `YAJL`, which contains two service programs: `YAJL` and `YAJLR4`.
It also contains a member `yajl_h` with all procedure prototypes.

## Decimal points

Json format requires decimal numbers to have a number before the decimal point.
Therefor don't forget to set the decimal edit on top of your program.

```
    ctl-opt    decedit('0.');
```

## Generating JSON

To build JSON, YAJL provides a set of procedures, called in order as the document is built up.


### Starting and ending the generator

To generate JSON data we first need to open the JSON generator for initialization. This can be done by :
```
    yajl_genOpen(*off);
    yajl_genOpen(*on);              // start generating, *on = human-readable output
```
When the optional parameter is *ON, YAJL will add line breaks and will indent the code for human readability.

Line breaks and indentation takes about 35% extra space of a total json.
When generating large JSON formats, this can be a lot more to transfer or to parse !


At the end we need to close the JSON generator by using `yajl_genClose()`.

```
   yajl_genOpen(*on);              

   // ...

   yajl_genClose();
```

### Composing json Objects

Json object can be created by using the procedures `yajl_beginObj()` / `yajl_endObj()` to open and close a json object.
Optionally the `yajl_beginObj()` procedure can have a a parameter to identify the name of the object.

```
   yajl_genOpen(*on);              // start generating, *on = human-readable output
   yajl_beginObj();                //  {

   yajl_addChar('name' : 'Jurgen');
   yajl_addNum('age' : 25);

   yajl_endObj();                  //  }

   json = yajl_copyBuf();

   yajl_genClose();
```

The key/value pairs are constructed by the following procedures :
- `yajl_addChar(key-name : variable-of-type-character)` adds character key/value
- `yajl_addNum(key-name : variable-of-type-character)` adds numeric key/value. Mind the second parameter is a character field.
- `yajl_addBool(key-name : variable-of-type-indicator)` adds boolean key/value
- `yajl_addNull(key-name)` adds null key/value


Arrays can be added as well by using  :
- `yajl_beginArray(optional-name-of-array)`
- `yajl_endArray()` 

## Exporting the json 
- `yajl_copyBuf()` copies everything built up so far out of YAJL's internal buffer, into a normal RPG variable.
- `yajl_saveBuf()` writes json to IFS
- `yajl_writeStdOut()` writes json to standard out (= browser)


## Parsing JSON : DATA-INTO

RPG has a native `data-into` operation that reads a JSON (or XML) document straight into an RPG data structure, using an external "parser" to do the actual work, `YAJLINTO` is the parser YAJL provides for this.
The YAJL installation comes with a parser written for this operation.

```
   dcl-ds invoice qualified;
      invoice varchar(10);
      date    varchar(10);
      name    varchar(50);
      amount  packed(9:2);
      weight  packed(7:2);
   end-ds;

   data-into invoice
      %data('/tmp/invoice.json' : 'doc=file case=convert')
      %parser('YAJLINTO');

   dsply invoice.name;
```

- `%data(source:options)`: the JSON to parse, and options controlling how. `doc=file` means the first value is a path to a file on the IFS, instead of the JSON text itself. `case=convert` allows the JSON field names to use a different case than the data structure's subfields.
- `%parser('YAJLINTO')`: the name of the parser service program that does the actual parsing.
- The data structure's subfields must match the JSON document's fields by name (case aside). The `list` array from the example above maps onto an array of data structures (see the Data structures chapter), one occurrence per invoice.
