# YAJL

## What is YAJL?

YAJL = Yet Another JSON Library

YAJL is a very fast tool for generating and parsing JSON.

We use YAJL mainly for generating JSON, because there are already (newer) solutions for parsing JSON, like `json_table` in SQL and `data-into` in RPG.

YAJL was originally written in C, but Scott Klement & David Russo ported it to IBM i.
It is available for downloading at http://www.scottklement.com/yajl


## JSON

Example of a JSON document:

```
{
    "success": true,
    "errmsg": "",
    "list": [
        {
            "invoice": "70689",
            "date": "03/01/2014",
            "name": "SCOTT KLEMENT",
            "amount": 14.80,
            "weight": 0.5
        },
        { another invoice },
        { another invoice },
        ...etc...
    ]
}
```


## Service program

The YAJL installation comes with a binding directory `YAJL`, which contains two service programs: `YAJL` and `YAJLR4`. It also contains a member `yajl_h` with all the procedure prototypes.


## Decimal points

JSON requires a decimal number to have a digit before the decimal point (`0.5`, not `.5`). Therefore, don't forget to set the decimal edit at the top of your program (see the Control statements chapter):

```
    ctl-opt decedit('0.');
```


## Generating JSON

To build JSON, YAJL provides a set of procedures, called in order as the document is built up.

### Starting and ending the generator

The JSON generator first needs to be opened for initialization, with one of:

```
    yajl_genOpen(*off);             // compact output
    yajl_genOpen(*on);              // human-readable output, with line breaks and indentation
```

Line breaks and indentation take up noticeably more space than compact output. When generating large JSON documents, this adds up to a lot more data to transfer or to parse.

At the end, the generator needs to be closed again, with `yajl_genClose()`.

```
   yajl_genOpen(*on);

   // ...

   yajl_genClose();
```

### Composing JSON objects

A JSON object is created with the procedures `yajl_beginObj()` / `yajl_endObj()`, to open and close it. Optionally, `yajl_beginObj()` can take a parameter to name the object.

```
   yajl_genOpen(*on);              // start generating, *on = human-readable output
   yajl_beginObj();                //  {

   yajl_addChar('name' : 'Jurgen');
   yajl_addNum('age' : 25);

   yajl_endObj();                  //  }

   json = yajl_copyBuf();

   yajl_genClose();
```

The key/value pairs are constructed with the following procedures:
- `yajl_addChar(key-name : variable-of-type-character)` adds a character key/value.
- `yajl_addNum(key-name : variable-of-type-character)` adds a numeric key/value. Mind that the second parameter is still a character field, the number has to be converted with `%char()` first.
- `yajl_addBool(key-name : variable-of-type-indicator)` adds a boolean key/value.
- `yajl_addNull(key-name)` adds a null key/value.

Arrays are added the same way, with:
- `yajl_beginArray(optional-name-of-array)`
- `yajl_endArray()`

Putting an array of objects together builds exactly the `list` from the JSON example above:

```
   dcl-ds invoiceRec qualified template;
      invoice varchar(10);
      date    varchar(10);
      name    varchar(50);
      amount  packed(9:2);
   end-ds;

   dcl-ds invoices likeds(invoiceRec) dim(50);
   dcl-s  i        int(5);

   // ... invoices gets filled from a file, a database, ...

   yajl_genOpen(*on);
   yajl_beginObj();

   yajl_addBool('success' : *on);
   yajl_addChar('errmsg'  : '');

   yajl_beginArray('list');

   for i = 1 to %elem(invoices);
      yajl_beginObj();
      yajl_addChar('invoice' : invoices(i).invoice);
      yajl_addChar('date'    : invoices(i).date);
      yajl_addChar('name'    : invoices(i).name);
      yajl_addNum ('amount'  : %char(invoices(i).amount));
      yajl_endObj();
   endfor;

   yajl_endArray();
   yajl_endObj();

   json = yajl_copyBuf();
   yajl_genClose();
```


## Exporting the JSON

```
   dcl-s   json               varchar(4096);
   dcl-s   httpstatus         packed(3) inz(200);
   dcl-s   errormsg           varchar(500);

   // Copy the buffer into a variable
   json = yajl_copyBuf();

   // Save the buffer to an ifs file
   yajl_saveBuf( '/home/jurgen/sales.json' : errormsg );

   // Write to stdout
   yajl_writeStdOut( httpstatus  : errormsg )

   yajl_genClose();
```

- `yajl_copyBuf()` copies everything built up so far out of YAJL's internal buffer, into a normal RPG variable.
- `yajl_saveBuf( path-to-ifs-file : error-message )` writes the JSON to the IFS.
- `yajl_writeStdOut( http-status-code : error-message )` writes the JSON to standard out (= the browser).


## Parsing JSON : DATA-INTO

RPG has a native `data-into` operation that reads a JSON (or XML) document straight into an RPG data structure, using an external "parser" to do the actual work, `YAJLINTO` is the parser the YAJL installation provides for this.

```
   dcl-ds invoiceRec qualified template;
      invoice varchar(10);
      date    varchar(10);
      name    varchar(50);
      amount  packed(9:2);
   end-ds;

   dcl-ds jsonDoc qualified;
      success  ind;
      errmsg   varchar(50);
      list     likeds(invoiceRec) dim(50);
      num_list int(10);
   end-ds;

   data-into jsonDoc
      %data('/tmp/invoices.json' : 'doc=file case=convert countprefix=num_')
      %parser('YAJLINTO');

   dsply jsonDoc.list(1).name;
   dsply %char(jsonDoc.num_list);         // how many invoices were actually found
```

- `%data(source:options)`: the JSON to parse, and options controlling how. `doc=file` means the first value is a path to a file on the IFS, instead of the JSON text itself. `case=convert` allows the JSON field names to use a different case than the data structure's subfields. `countprefix=num_` gives every array subfield a matching count field, prefixed `num_`, here `num_list` tells how many invoices were actually parsed into `list`.
- `%parser('YAJLINTO')`: the name of the parser service program that does the actual parsing.
- The data structure's subfields must match the JSON document's fields by name (case aside). The `list` array maps onto a `dim()`'d array of data structures, built with `likeds`/`template` (see the Data structures chapter), one occurrence per invoice.
