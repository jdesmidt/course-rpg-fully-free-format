# 3.1.2 - A service program with binder language

**Topics practiced:** `export`, `CRTSRVPGM`, binder language (`STRPGMEXP`/`ENDPGMEXP`).

**Description:** turn the `MATHUTIL` module from exercise 3.1.1 into a service program, so it can be recreated on its own without touching every calling program.


## Steps

1. Reuse the `MATHUTIL` module unchanged, add `export` to the `roundAmount` procedure declaration.
2. Write binder source in member `QSRVSRC(MATHUTIL)`, with `STRPGMEXP PGMLVL(*CURRENT) SIGNATURE('MATHUTIL V1.00  ')`, one `export symbol(roundAmount)` line, and `ENDPGMEXP`.
3. Create the module with `CRTRPGMOD`, then the service program with `CRTSRVPGM SRVPGM(MYLIB/MATHUTIL) MODULE(MYLIB/MATHUTIL) SRCFILE(MYLIB/QSRVSRC)`.
4. Discuss: why can a service program not be called directly with `CALL`, unlike a normal program?


## Solution

Module, `QRPGLESRC(MATHUTIL)`:
```
**free
ctl-opt nomain;

/copy qcpysrc,mathutil_h

dcl-proc roundAmount export;
   dcl-pi *n packed(9:2);
      pAmount packed(9:4) const;
   end-pi;

   return %dec(pAmount:9:2);         // rounds to 2 decimals
end-proc;
```

Binder source, `QSRVSRC(MATHUTIL)`:
```
STRPGMEXP PGMLVL(*CURRENT) SIGNATURE('MATHUTIL V1.00  ')
   export symbol(roundAmount)
ENDPGMEXP
```

Create commands:
```
CRTRPGMOD MODULE(MYLIB/MATHUTIL) SRCFILE(MYLIB/QRPGLESRC)

CRTSRVPGM SRVPGM(MYLIB/MATHUTIL) MODULE(MYLIB/MATHUTIL) SRCFILE(MYLIB/QSRVSRC)
```

- `export` on `roundAmount` makes it callable from other modules, without it the procedure would stay private to this one module.
- A service program has one entry point per exported procedure instead of one single program entry, that is exactly why there is no single thing for `CALL` to call.
- `STRPGMEXP`/`ENDPGMEXP` hand-control the export signature, so `MATHUTIL` can later gain new procedures (as new `export symbol` lines) without changing the signature that existing callers already compiled against.
