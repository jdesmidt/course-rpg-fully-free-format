# 1.3.2 - Find the bugs

**Topics practiced:** F6, F10, F11, F12, used to actually find a real problem.

**Description:** `buggy.rpgle` compiles cleanly, but produces wrong results, find and fix all 3 bugs using the debugger, not by just reading the source.


## Steps

1. Compile `buggy.rpgle` (below) into a program.
2. `STRDBG PGM(MYLIB/BUGGY) UPDPROD(*YES);`, set a breakpoint (**F6**) on the first line inside the `for` loop.
3. `CALL MYLIB/BUGGY`, step through with **F10**, and use **F11** to display `i`, `wScores(i)` and `wTotal` as you go.
4. Does the loop process all 5 scores? Is a score of exactly `50` shown as `Pass` or `Fail`, should it be? Once the loop ends, does `wAverage` look like a real average?
5. Fix each bug you find, one at a time, recompiling and re-running the debugger session after each fix.


## Solution

There are 3 deliberate bugs: the loop stops one score too early, the pass/fail boundary is wrong, and the average is never actually divided.

```
**free
// buggy.rpgle

dcl-s wScores packed(5:2) dim(5);
dcl-s wTotal   packed(7:2) inz(0);
dcl-s wAverage packed(5:2);
dcl-s i        int(5);

wScores(1) = 45.0;
wScores(2) = 62.0;
wScores(3) = 50.0;
wScores(4) = 78.0;
wScores(5) = 91.0;

for i = 1 to 4;                            // bug: should be %elem(wScores), skips the 5th score

   dsply wScores(i);

   if wScores(i) > 50;                     // bug: should be >=, a score of exactly 50 shows 'Fail'
      dsply 'Pass';
   else;
      dsply 'Fail';
   endif;

   wTotal += wScores(i);

endfor;

wAverage = wTotal;                         // bug: never actually divided by %elem(wScores)

dsply %editc(wTotal:'1');
dsply wAverage;

*inlr = *on;
```
