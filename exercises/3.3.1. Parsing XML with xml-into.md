# 3.3.1 - Parsing XML with xml-into

**Topics practiced:** `xml-into`, `%xml()` options, wrapping it in `monitor`/`on-error`.

**Description:** parse a small login-style XML document straight into a qualified data structure.


## Steps

1. Declare a qualified data structure `qrcode` with `env` (char 20), `type` (char 64), `user` (varchar 64), `pasw` (varchar 64).
2. Build an XML string in a variable, with a root `<QR>` element containing `<ENV>`, `<TYPE>`, `<USER>`, `<PASW>` and an extra `<SESSIONID>` that `qrcode` does not have a subfield for.
3. Build the options string: `doc=string allowextra=yes allowmissing=yes case=any path=QR`.
4. `xml-into qrcode %xml(xmldata : xmloptions);`, wrapped in `monitor`/`on-error`.
5. Display `qrcode.user`, and confirm the extra `<SESSIONID>` element did not cause an error.


## Solution

```
**free

dcl-ds qrcode qualified;
   env  char(20);
   type char(64);
   user varchar(64);
   pasw varchar(64);
end-ds;

dcl-s wXmlData    varchar(1000);
dcl-s wXmlOptions char(256) inz('doc=string allowextra=yes allowmissing=yes case=any path=QR');

wXmlData = '<QR>' +
              '<ENV>PROD</ENV>' +
              '<TYPE>LOGIN</TYPE>' +
              '<USER>jdesmidt</USER>' +
              '<PASW>Secr3t!</PASW>' +
              '<SESSIONID>AB12CD34</SESSIONID>' +
           '</QR>';

monitor;
   xml-into qrcode %xml(wXmlData : wXmlOptions);
on-error;
   dsply 'invalid XML';
endmon;

dsply qrcode.user;                  // 'jdesmidt'

*inlr = *on;
```

- `path=QR` tells `xml-into` to start matching from the `<QR>` element, so `qrcode`'s subfields correspond to its direct children.
- `allowextra=yes` is what lets `<SESSIONID>`, an element `qrcode` has no matching subfield for, pass through without raising an error.
- `xml-into` is a built-in RPG operation, unlike JSON parsing (`data-into`/YAJL, next exercises), no external service program is needed for XML.
