# 1.3.4 - From fixed format to free format, then debug it

**Topics practiced:** reading classic fixed-format RPG (H/D/C-specs), rewriting it in Fully Free Format, `STRDBG`, F6/F10/F11, the debugger's `EVAL` command.

**Description:** rewrite a small fixed-format program in free format, then debug your own version: check that every field gets the value it should, and use `EVAL` to change one while the program is paused.


## Part 1 - Rewrite in free format

Here is a small, classic fixed-format program. It declares a few fields of different types, gives them a value, and composes a message out of them.

```
H DATFMT(*ISO)

D wName           S             20A
D wAge            S              3S 0
D wSalary         S              9S 2
D wMessage        S             80A   VARYING

C                   EVAL      wName = 'Jurgen Desmidt'
C                   EVAL      wAge = 25
C                   EVAL      wSalary = 3500.75

C                   EVAL      wMessage = %TRIM(wName) + ' is ' +
C                                        %CHAR(wAge) + ' years old, ' +
C                                        'earning ' + %CHAR(wSalary)

C                   DSPLY                   wMessage

C                   SETON                                        LR
```

1. Read through the fixed-format source above before typing anything, identify the 4 fields and their types (`char`, `zoned`, `packed`, `varchar`).
2. Create a new, Fully Free Format source member, and rewrite the same logic: `**free`, `dcl-s` for each field (matching type and length), `eval` (or plain `=`) for each assignment, `dsply` for the message, `*inlr = *on;` instead of `SETON LR`.
3. Compile it, run it, and check the message reads correctly.


## Part 2 - Debug it

4. `STRDBG PGM(MYLIB/yourpgm) UPDPROD(*YES);`
5. Put the cursor on the `wMessage = ...` line (the one composing the message), press **F6** to set a breakpoint there.
6. `CALL MYLIB/yourpgm`, the debugger stops right before that line runs.
7. Use **F11** (or the debugger command line, see step 8) on `wName`, `wAge` and `wSalary`, one at a time, confirm each already holds the value it was assigned earlier in the program.
8. On the debugger's command line, type `EVAL wAge = 40` and press Enter, this changes `wAge` while the program is still paused.
9. Press **F10** (or **F12**) to let the `wMessage = ...` line run, then check `wMessage` (F11, or just let the program finish and read the `dsply`): it should now show `40`, not `25`, proving the message was built from the value you just typed in, not from the original assignment.
10. Press **F3** to end the debug session.


## Solution

### Part 1 - free format rewrite

```
**free

dcl-s wName    char(20);
dcl-s wAge     zoned(3:0);
dcl-s wSalary  packed(9:2);
dcl-s wMessage varchar(80);

wName   = 'Jurgen Desmidt';
wAge    = 25;
wSalary = 3500.75;

wMessage = %trim(wName) + ' is ' +
           %char(wAge) + ' years old, ' +
           'earning ' + %char(wSalary);

dsply wMessage;

*inlr = *on;
```

- `S` (standalone field) on the D-specs corresponds to `dcl-s`, `20A` to `char(20)`, `3S 0` to `zoned(3:0)`, `9S 2` to `packed(9:2)`, and the `VARYING` keyword to `varchar(80)`.
- `SETON LR` is the fixed-format way to turn on `*inlr`, this program has no primary file, so (exactly as chapter 120 explains) it has to be set explicitly, or the cycle would call the program again and again.

### Part 2 - debug session

```
STRDBG PGM(MYLIB/YOURPGM) UPDPROD(*YES);
-- F6 on the "wMessage = ..." line
CALL MYLIB/YOURPGM
-- F11 on wName, wAge, wSalary: confirm 'Jurgen Desmidt', 25, 3500.75
EVAL wAge = 40
-- F10 to run the wMessage = ... line
-- F11 on wMessage: 'Jurgen Desmidt is 40 years old, earning 3500.75'
```

- Changing `wAge` before the message is composed is what makes the change visible, `EVAL` after that line would still update `wAge` itself, but `wMessage` would already have been built from the old value.
