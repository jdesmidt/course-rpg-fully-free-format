# 3.2.1 - Reading and writing a data area

**Topics practiced:** `dtaara('name')`, `in`, `out`.

**Description:** read a configuration value from a data area, change it, and write it back.


## Steps

1. Assume a data area `MAXORDERS` already exists (created outside RPG with `CRTDTAARA DTAARA(MYLIB/MAXORDERS) TYPE(*DEC) LEN(5 0)`).
2. Declare `wMaxOrders`, `zoned(5)`, linked to it with `dtaara('MAXORDERS')`.
3. `in` the current value, and display it.
4. Add `10` to it, and `out` the new value back to the data area.
5. `in` it again, to confirm the change was saved.


## Solution

```
**free

dcl-s wMaxOrders zoned(5) dtaara('MAXORDERS');

in wMaxOrders;
dsply wMaxOrders;

wMaxOrders += 10;
out wMaxOrders;

in wMaxOrders;
dsply wMaxOrders;             // 10 higher than the first display
```

- `dtaara('MAXORDERS')` links the field directly to that named data area, found through the library list, exactly like the special value `*lda` links a field to the Local Data Area.
- Without `*lock` (see the next exercise), nothing prevents two jobs from reading, changing and writing the same value at the same time, and one job's update overwriting the other's.
