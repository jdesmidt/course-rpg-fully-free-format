# 3.1.3 - Calling a service program through a binding directory

**Topics practiced:** `CRTBNDDIR`, `ADDBNDDIRE`, `ctl-opt bnddir(...)`, binding by reference.

**Description:** call the `MATHUTIL` service program from exercise 3.1.2 through a binding directory, instead of naming it directly on `CRTPGM`.


## Steps

1. Create a binding directory with `CRTBNDDIR BNDDIR(MYLIB/MYPGMS)`.
2. Add the service program to it with `ADDBNDDIRE BNDDIR(MYLIB/MYPGMS) OBJ((MYLIB/MATHUTIL *SRVPGM))`.
3. In the calling program, add `bnddir('MYPGMS')` to its `ctl-opt`, alongside `dftactgrp(*no) actgrp(*caller)`, `/copy` the prototype, and call `roundAmount` exactly as before.
4. Compile the module and `CRTPGM`, without naming `MATHUTIL` anywhere on the `CRTPGM` command itself.
5. Discuss: what has to change if `MATHUTIL` is later replaced by a different service program with the same exported procedures?


## Solution

```
CRTBNDDIR BNDDIR(MYLIB/MYPGMS)
ADDBNDDIRE BNDDIR(MYLIB/MYPGMS) OBJ((MYLIB/MATHUTIL *SRVPGM))
```

Calling program, `QRPGLESRC(ORDER001)`:
```
**free
ctl-opt dftactgrp(*no) actgrp(*caller) bnddir('MYPGMS');

/copy qcpysrc,mathutil_h

dcl-s wRounded packed(9:2);

wRounded = roundAmount(12.3456);

dsply wRounded;                      // 12.35

*inlr = *on;
```

```
CRTRPGMOD MODULE(MYLIB/ORDER001) SRCFILE(MYLIB/QRPGLESRC)

CRTPGM PGM(MYLIB/ORDER001) MODULE(MYLIB/ORDER001)
```

- `ORDER001` only keeps a pointer to `MATHUTIL` through the binding directory ("bind by reference"), the procedure's compiled code is not copied in.
- If `MATHUTIL` is replaced later, only the binding directory entry needs to change, `ORDER001` does not need to be recreated, as long as the export signature stays compatible.
