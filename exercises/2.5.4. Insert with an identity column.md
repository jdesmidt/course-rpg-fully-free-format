# 2.5.4 - Insert with an identity column

**Topics practiced:** `insert`, `identity_val_local()`, `get diagnostics`.

**Description:** insert a new supplier (its primary key is an identity column), retrieve the generated id, then update that supplier's city and report how many rows were affected.


## Steps

1. Reuse the `suppliers` table from exercise 2.5.2 (DDL below), no change is needed to the table itself. `ORDERS` (the DDS file from exercises 2.4.2/2.4.3) is not used here, DDS has no way to define an identity column, this is exactly why `suppliers` is a plain SQL table instead.
2. `insert` a row into `suppliers` with `supplierName` and `city`, leaving the identity column (`supplierId`) out of the column list entirely.
3. Retrieve the generated key right after with `select identity_val_local() as last_id into :wSupplierId from sysibm.sysdummy1;`.
4. Display `wSupplierId`.
5. `update` that supplier's `city`, then use `get diagnostics :wRowsUpdated = row_count;` to display how many rows were changed.


## Solution

### The table

```sql
CREATE TABLE suppliers (
   supplierId   DEC(7, 0) GENERATED BY DEFAULT AS IDENTITY (START WITH 2000) NOT NULL,
   supplierName CHAR(30),
   city         CHAR(20),
   PRIMARY KEY (supplierId)
);

INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1001, 'Acme Supplies', 'Antwerp');
INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1002, 'Beta Parts', 'Antwerp');
INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1003, 'Gamma Trading', 'Brussels');
```

### The program

```
**free

dcl-s wSupplierName char(30) inz('Delta Logistics');
dcl-s wCity          char(20) inz('Ghent');
dcl-s wSupplierId    packed(7:0);
dcl-s wRowsUpdated   int(10);

exec sql
   insert into suppliers (supplierName, city)
     values (:wSupplierName, :wCity);

exec sql
   select identity_val_local() as last_id
     into :wSupplierId
     from sysibm.sysdummy1;

dsply wSupplierId;

exec sql
   update suppliers
      set city = 'Antwerp'
    where supplierId = :wSupplierId;

exec sql get diagnostics :wRowsUpdated = row_count;

dsply wRowsUpdated;                    // 1

*inlr = *on;
```

- `identity_val_local()` must be called right after the `insert` that generated the value, and before any other `insert` happens on the same connection.
- `row_count` (through `get diagnostics`) works after an `insert`, `update`, `delete`, singleton `select into`, or `fetch`.
- `supplierId` is `GENERATED BY DEFAULT AS IDENTITY`, leaving it out of the column list here is what makes the database generate the next value automatically, starting from `2000`, well clear of the explicit ids (`1001`-`1003`) inserted in exercise 2.5.2.
