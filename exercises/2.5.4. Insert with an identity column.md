# 2.5.4 - Insert with an identity column

**Topics practiced:** `insert`, `identity_val_local()`, `get diagnostics`.

**Description:** insert a new order (its primary key is an identity column) and retrieve the generated id, then update its status and report how many rows were affected.


## Steps

1. `insert` a row into `orders` with `custNr` and `orderDate`, leaving the identity column out of the column list entirely.
2. Retrieve the generated key right after with `select identity_val_local() as last_cod into :wOrderId from sysibm.sysdummy1;`.
3. Display `wOrderId`.
4. `update` that order's `status` to `'SHIPPED'`, then use `get diagnostics :wRowsUpdated = row_count;` to display how many rows were changed.


## Solution

```
**free

dcl-s wCustNr    packed(7:0) inz(1001);
dcl-s wOrderDate date(*iso)  inz(*sys);
dcl-s wOrderId   packed(9:0);
dcl-s wRowsUpdated int(10);

exec sql
   insert into orders (custNr, orderDate)
     values (:wCustNr, :wOrderDate);

exec sql
   select identity_val_local() as last_cod
     into :wOrderId
     from sysibm.sysdummy1;

dsply wOrderId;

exec sql
   update orders
      set status = 'SHIPPED'
    where orderId = :wOrderId;

exec sql get diagnostics :wRowsUpdated = row_count;

dsply wRowsUpdated;                    // 1

*inlr = *on;
```

- `identity_val_local()` must be called right after the `insert` that generated the value, and before any other `insert` happens on the same connection.
- `row_count` (through `get diagnostics`) works after an `insert`, `update`, `delete`, singleton `select into`, or `fetch`.
