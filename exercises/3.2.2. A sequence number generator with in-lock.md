# 3.2.2 - A sequence number generator with in *lock

**Topics practiced:** `in *lock`, `unlock`, safely handing out a unique number across jobs.

**Description:** write a small procedure that hands out the next order number from a `COUNTER` data area, safe even when called from multiple jobs at once.


## Steps

1. Declare `sequence`, `zoned(9)`, linked to `dtaara('COUNTER')`.
2. `in *lock sequence;` to read the current value and lock the data area.
3. If `sequence` is already at its maximum (`999999999`), `unlock` it and return `0` without changing anything.
4. Otherwise, add 1 to `sequence`, `out sequence;` to write it back and release the lock, and return the new value.
5. Explain what would go wrong if `in` (without `*lock`) were used instead, when two jobs call this at the exact same moment.


## Solution

```
**free

dcl-s sequence zoned(9) dtaara('COUNTER');

dsply nextOrderNr();
dsply nextOrderNr();

*inlr = *on;

dcl-proc nextOrderNr;
   dcl-pi nextOrderNr zoned(9);
   end-pi;

   in *lock sequence;

   if sequence >= 999999999;
      unlock sequence;             // give up the lock, change nothing
      return 0;
   endif;

   sequence += 1;
   out sequence;                   // write the new value back, and release the lock

   return sequence;
end-proc;
```

- `in *lock` locks the data area exclusively, no other job can `in *lock` or `out` it until this job releases the lock, this is what prevents two jobs from handing out the same number.
- Without `*lock`, two jobs could both `in` the same value, both add 1, and both `out` the same result, one increment would be silently lost.
