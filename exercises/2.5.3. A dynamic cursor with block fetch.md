# 2.5.3 - A dynamic cursor with block fetch

**Topics practiced:** `prepare`, a dynamic cursor, fetching multiple rows at once into an array.

**Description:** build the `where` clause of a query at run time, and fetch its results in batches of 100 rows for speed.


## Steps

1. Build the SQL text in a variable, for example selecting customers from a city that is only known at run time.
2. `exec sql prepare stmt from :wSqlText;`, then `declare custCur cursor for stmt;`, then `open custCur;`.
3. Declare `wCustomer`, a qualified data structure array, `dim(100)`, with `custNr` and `custName`.
4. `fetch next from custCur for 100 rows into :wCustomer;`, and loop over the filled elements with `for-each`.
5. `close` the cursor.


## Solution

```
**free

dcl-s wCity   char(20) inz('Antwerp');
dcl-s wSqlTxt varchar(500);

wSqlTxt = 'select custNr, custName from customers where city = ''' + %trim(wCity) + '''';

exec sql prepare stmt from :wSqlTxt;
exec sql declare custCur cursor for stmt;
exec sql open custCur;

dcl-ds wCustomer dim(100) qualified;
   custNr   packed(7:0);
   custName char(30);
end-ds;

exec sql fetch next from custCur for 100 rows into :wCustomer;

dcl-s wOneCustomer likeds(wCustomer);
for-each wOneCustomer in wCustomer;
   if wOneCustomer.custNr > 0;
      dsply wOneCustomer.custName;
   endif;
endfor;

exec sql close custCur;

*inlr = *on;
```

- Because the SQL text is only known at run time (built up in `wSqlTxt`), a `prepare` step is required before the cursor can be declared, this is what makes it "dynamic".
- `for 100 rows into :wCustomer` fills as many of the 100 array elements as there are remaining rows in one round trip, `get diagnostics` (see the Embedded SQL chapter) reports exactly how many.
