# 2.5.3 - A dynamic cursor with block fetch

**Topics practiced:** `prepare`, a dynamic cursor, fetching multiple rows at once into an array.

**Description:** build the `where` clause of a query at run time, and fetch its results in batches of 100 rows for speed.


## Steps

1. Reuse the `suppliers` table from exercise 2.5.2 (DDL below), no change is needed to the table itself.
2. Build the SQL text in a variable, for example selecting suppliers from a city that is only known at run time.
3. `exec sql prepare stmt from :wSqlText;`, then `declare supCur cursor for stmt;`, then `open supCur;`.
4. Declare `wSupplier`, a qualified data structure array, `dim(100)`, with `supplierId` and `supplierName`.
5. `fetch next from supCur for 100 rows into :wSupplier;`, and loop over the filled elements with `for-each`.
6. `close` the cursor.


## Solution

### The table

```sql
CREATE TABLE suppliers (
   supplierId   DEC(7, 0) GENERATED BY DEFAULT AS IDENTITY (START WITH 2000) NOT NULL,
   supplierName CHAR(30),
   city         CHAR(20),
   PRIMARY KEY (supplierId)
);

INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1001, 'Acme Supplies', 'Antwerp');
INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1002, 'Beta Parts', 'Antwerp');
INSERT INTO suppliers (supplierId, supplierName, city) VALUES (1003, 'Gamma Trading', 'Brussels');
```

### The program

```
**free

dcl-s wCity   char(20) inz('Antwerp');
dcl-s wSqlTxt varchar(500);

dcl-ds wSupplier dim(100) qualified;
   supplierId   packed(7:0);
   supplierName char(30);
end-ds;

dcl-s wOneSupplier likeds(wSupplier);

wSqlTxt = 'select supplierId, supplierName from suppliers where city = ''' + %trim(wCity) + '''';

exec sql prepare stmt from :wSqlTxt;
exec sql declare supCur cursor for stmt;
exec sql open supCur;

exec sql fetch next from supCur for 100 rows into :wSupplier;

for-each wOneSupplier in wSupplier;
   if wOneSupplier.supplierId > 0;
      dsply wOneSupplier.supplierName;
   endif;
endfor;

exec sql close supCur;

*inlr = *on;
```

- Because the SQL text is only known at run time (built up in `wSqlTxt`), a `prepare` step is required before the cursor can be declared, this is what makes it "dynamic".
- `for 100 rows into :wSupplier` fills as many of the 100 array elements as there are remaining rows in one round trip, `get diagnostics` (see the Embedded SQL chapter) reports exactly how many.
