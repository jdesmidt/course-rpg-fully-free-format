# 2.2.4 - Main procedure and on-exit

**Topics practiced:** `ctl-opt main()`, `on-exit`.

**Description:** replace the program's loose calculation statements with a main procedure, and guarantee cleanup code always runs through `on-exit`.


## Steps

1. Declare `ctl-opt main(main);`, then a procedure `main`, with a `char(1)` parameter `pRtcd` (its `dcl-pi` uses `*n` as the name, since there is no separate prototype).
2. Inside `main`, allocate 100 bytes into a pointer with `%alloc`, display a message, then `return;`.
3. Add an `on-exit` block after the `return`, that deallocates the pointer with `dealloc`, and displays `'cleanup done'`.
4. Remember: with `main()`, the RPG cycle is bypassed entirely, there is no `*inlr` anywhere in this program.


## Solution

```
**free
ctl-opt main(main);

dcl-proc main;
   dcl-pi *n;
      pRtcd char(1);
   end-pi;

   dcl-s wPtr pointer;

   wPtr = %alloc(100);

   dsply 'Hello world';

   return;

   on-exit;
      dealloc wPtr;
      dsply 'cleanup done';
end-proc;
```

- `on-exit` always runs, whichever `return` was reached, or even after an unhandled error, this makes it the natural place for cleanup like `dealloc`, closing files, or unlocking data areas.
- Because there is no RPG cycle here, nothing is closed/unlocked automatically, only `on-exit` (or explicit code before `return`) guarantees cleanup.
