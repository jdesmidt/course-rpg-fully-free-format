# 3.3.4 - Parsing JSON with data-into and YAJLINTO

**Topics practiced:** `data-into`, `%data()`, `%parser('YAJLINTO')`, `countprefix`.

**Description:** parse a JSON file of invoices straight into an array of data structures, using RPG's native `data-into` with the YAJL parser.


## Steps

1. Declare an `invoiceRec` template (`invoice`, `date`, `name`, `amount`), and a qualified `jsonDoc` data structure with `success` (ind), `errmsg` (varchar), `list` (`likeds(invoiceRec) dim(50)`) and `num_list` (int).
2. Assume a file `/tmp/invoices.json` already exists on the IFS, in the same shape as the `success`/`errmsg`/`list` example from the YAJL chapter.
3. `data-into jsonDoc %data('/tmp/invoices.json' : 'doc=file case=convert countprefix=num_') %parser('YAJLINTO');`.
4. Display `jsonDoc.list(1).name`, and `jsonDoc.num_list`, the actual number of invoices found.


## Solution

```
**free

dcl-ds invoiceRec qualified template;
   invoice varchar(10);
   date    varchar(10);
   name    varchar(50);
   amount  packed(9:2);
end-ds;

dcl-ds jsonDoc qualified;
   success  ind;
   errmsg   varchar(50);
   list     likeds(invoiceRec) dim(50);
   num_list int(10);
end-ds;

data-into jsonDoc
   %data('/tmp/invoices.json' : 'doc=file case=convert countprefix=num_')
   %parser('YAJLINTO');

dsply jsonDoc.list(1).name;
dsply %char(jsonDoc.num_list);         // how many invoices were actually found

*inlr = *on;
```

- `countprefix=num_` is why `num_list` gets filled in automatically with the real number of invoices parsed, `list` itself always keeps its declared size (`dim(50)`), any unused occurrences are simply left at their initial value.
- `case=convert` allows the JSON's field names to use different case (or characters like `-`) than the RPG subfield names, matching them regardless.
