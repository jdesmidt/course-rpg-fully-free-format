# 2.3.1 - Prototyping and calling a program

**Topics practiced:** `dcl-pr`/`extpgm`, calling an external `*PGM`.

**Description:** write a small `CALCTAX` program, prototype it, and call it from a caller program.


## Steps

1. In a separate source member `CALCTAX`, declare `dcl-pi *n;` with `pAmount` (const), `pRate` (const) and `pTax` (outgoing, no `const`), all `packed`.
2. Inside, calculate `pTax = pAmount + (pAmount * pRate / 100);`, and set `*inlr = *on;`.
3. In the caller program, declare a prototype `calcTax` with `extpgm('CALCTAX')` and the exact same parameter list.
4. Call it as `calcTax(100 : 21 : wTax);`, and display `wTax`.
5. Note that a `*PGM` call has no return value, `pTax` is the only way results come back.


## Solution

CALCTAX (called program):
```
**free
dcl-pi *n;
   pAmount packed(7:2) const;
   pRate   packed(5:2) const;
   pTax    packed(9:2);
end-pi;

pTax = pAmount + (pAmount * pRate / 100);

*inlr = *on;
```

Caller program:
```
**free

dcl-pr calcTax extpgm('CALCTAX');
   pAmount packed(7:2) const;
   pRate   packed(5:2) const;
   pTax    packed(9:2);
end-pr;

dcl-s wTax packed(9:2);

calcTax(100 : 21 : wTax);
dsply wTax;                    // 121.00

*inlr = *on;
```

- `extpgm('CALCTAX')` lets the RPG name (`calcTax`) differ from the actual object name (`CALCTAX`, at most 10 characters).
- The two programs are compiled separately, the compiler cannot verify their parameter lists match, keeping the prototype in a `/copy` member shared by both avoids mismatches.
