# 2.5.1 - Singleton select and exists check

**Topics practiced:** `exec sql`, host variables, `set option`, singleton `select ... into`, checking existence via `sqlcode`.

**Description:** look up one employee's name by id, then check whether a customer number exists without reading any of its columns.


## Steps

1. Add `exec sql set option naming = *sys, commit = *none, datfmt = *iso;` as the very first SQL statement.
2. Declare `wEmpId`, `wFirstName`, `wLastName` and fetch the employee's name with a singleton `select ... into`, using `fetch first 1 row only`.
3. Declare an indicator `wExists`, and check whether a customer exists by selecting the constant `1` into it, instead of `select count(*)`.
4. Display `'Customer exists'` or `'Customer not found'` based on `wExists`.


## Solution

```
**free
exec sql set option naming = *sys, commit = *none, datfmt = *iso;

dcl-s wEmpId     packed(7:0) inz(1234);
dcl-s wFirstName char(20);
dcl-s wLastName  char(20);
dcl-s wCustNr    packed(7:0) inz(1001);
dcl-s wExist     ind inz(*off);

exec sql
   select firstName, lastName
     into :wFirstName, :wLastName
     from employees
    where empId = :wEmpId
    fetch first 1 row only;

dsply (%trim(wFirstName) + ' ' + %trim(wLastName));

exec sql
   select 1
     into :wExist
     from customers
    where custNr = :wCustNr
    fetch first 1 row only;

if wExist;
   dsply 'Customer exists';
else;
   dsply 'Customer not found';
endif;

*inlr = *on;
```

- `select 1 into :wExist` lets the database stop looking as soon as one matching row is found, cheaper than `select count(*)`.
- `fetch first 1 row only` avoids an error if the query could technically return more than one row.
