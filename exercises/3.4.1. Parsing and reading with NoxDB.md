# 3.4.1 - Parsing and reading with NoxDB

**Topics practiced:** `json_parseString`, `json_error`/`json_message`, `json_getStr`/`json_getBool`, node path expressions.

**Description:** parse a small JSON document into a NoxDB node tree, and read a few values out of it.


## Steps

1. Add `ctl-opt bnddir('JSONPARSER');` and `/copy qcpysrc,jsonparser`.
2. Build a JSON string in a variable: `{"cucompanyname":"CD Invest","cublocked":false}`.
3. Parse it with `json_parseString`, into a pointer `pCompany`.
4. Check `json_error()`, display `json_message()` when it failed.
5. Read `cucompanyname` with `json_getStr`, and `cublocked` with `json_getBool`, and display both.
6. Release the node with `json_delete`.


## Solution

```
**free
ctl-opt bnddir('JSONPARSER');

/copy qcpysrc,jsonparser

dcl-s wJsonText   varchar(200);
dcl-s pCompany    pointer;
dcl-s wCompanyName varchar(128);
dcl-s wBlocked     ind;

wJsonText = '{"cucompanyname":"CD Invest","cublocked":false}';

pCompany = json_parseString(wJsonText);

if json_error();
   dsply json_message();
else;
   wCompanyName = json_getStr(pCompany : 'cucompanyname');
   wBlocked     = json_getBool(pCompany : 'cublocked');

   dsply wCompanyName;               // 'CD Invest'
   dsply wBlocked;                   // *off
endif;

json_delete(pCompany);

*inlr = *on;
```

- `json_parseString` works on JSON already in a variable, `json_parseFile` reads the same kind of document straight from the IFS instead, everything after parsing is identical.
- `json_getStr`/`json_getBool`/... names come directly from the document's own field names, not from an RPG naming convention.
- Every node returned by `json_parseString` must eventually be released with `json_delete`, NoxDB does not garbage collect it automatically.
