# 2.3.4 - Error handling with monitor and on-error

**Topics practiced:** `callp(e)`/`%error()`/`%status()`, `monitor`/`on-error`/`endmon`.

**Description:** catch a division-by-zero error two different ways, once with `callp(e)`, once with `monitor`, distinguishing it from other errors.


## Steps

1. Declare `wAmount`, `wDivisor` and `wResult`, all numeric, with `wDivisor` set to `0`.
2. Write a procedure `divide` that returns `wAmount / wDivisor`.
3. Call it with `callp(e)`, check `%error()`, and display `%status()` when it failed.
4. Now do the same calculation directly (no procedure) inside a `monitor` block, with a specific `on-error 00102` for division by zero, and an `on-error *all` for anything else.
5. Change `wDivisor` to a non-zero value and confirm neither `on-error` block runs.


## Solution

```
**free

dcl-s wAmount  packed(9:2) inz(100);
dcl-s wDivisor packed(9:2) inz(0);
dcl-s wResult  packed(9:2);

callp(e) wResult = divide(wAmount : wDivisor);
if %error();
   dsply %char(%status());          // numeric status code of the error
endif;

monitor;
   wResult = wAmount / wDivisor;
on-error 00102;
   dsply 'division by zero';
   wResult = 0;
on-error *all;
   dsply %char(%status());          // any other error
endmon;

wDivisor = 5;
monitor;
   wResult = wAmount / wDivisor;
   dsply wResult;                   // 20.00, no error, both on-error blocks skipped
on-error *all;
   dsply %char(%status());
endmon;

*inlr = *on;

dcl-proc divide;
   dcl-pi divide packed(9:2);
      pAmount  packed(9:2) const;
      pDivisor packed(9:2) const;
   end-pi;

   return pAmount / pDivisor;
end-proc;
```

- `callp(e)` only ever gives a yes/no through `%error()`, `monitor`/`on-error` can react differently depending on the exact status code.
- `on-error 00102` only catches that one status code, anything else falls through to `on-error *all`.
