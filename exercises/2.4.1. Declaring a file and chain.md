# 2.4.1 - Declaring a file and chain

**Topics practiced:** `dcl-f`, `usage`, `keyed`, `chain`, `%found`.

**Description:** look up one customer directly by key from a `CUSTOMERS` file.


## Steps

1. Create the `CUSTOMERS` physical file (DDS below), and insert a row for customer `1001`.
2. Declare `dcl-f customers keyed;` (default `usage` is `*input`, which is all a lookup needs).
3. Declare a numeric field `wCustNr`, set it to an existing customer number.
4. `chain` on `wCustNr` into `customers`.
5. Check `%found(customers)`, display the customer's name when found, otherwise display `'not found'`.
6. Repeat with a customer number that does not exist, and confirm the `not found` message.


## Solution

### The file

DDS source, member `CUSTOMERS`:
```
     A          R CUSTREC
     A            CUSTNR         7S 0
     A            CUSTNAME      30A
     A          K CUSTNR
```

```
CRTPF FILE(MYLIB/CUSTOMERS) SRCFILE(MYLIB/QDDSSRC) SRCMBR(CUSTOMERS)
```

```sql
INSERT INTO MYLIB/CUSTOMERS VALUES (1001, 'Jurgen Desmidt');
```

### The program

```
**free

dcl-f customers keyed;

dcl-s wCustNr packed(7:0) inz(1001);

chain wCustNr customers;

if %found(customers);
   dsply custName;
else;
   dsply 'not found';
endif;

*inlr = *on;
```

- `keyed` is required before `chain` can be used with an actual key value, without it the file can only be read sequentially.
- `%found(file)` must be checked right after `chain`, the fields of the record format only hold meaningful values when a record was actually found.
- `K CUSTNR` on the DDS is what makes `CUSTNR` the key, without it the file could still be declared `keyed` in RPG, but there would be no key to `chain` on. Field names are not case-sensitive, `CUSTNR`/`CUSTNAME` in the DDS are the same fields as `wCustNr`'s target `custNr`/`custName` in the RPG code.
