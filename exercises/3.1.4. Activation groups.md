# 3.1.4 - Activation groups

**Topics practiced:** `ACTGRP(*NEW)`/`ACTGRP(*CALLER)`/`ACTGRP(name)`, `ctl-opt dftactgrp(*no) actgrp(...)`.

**Description:** compile the same two programs from exercise 3.1.1 into a shared, named activation group, instead of each getting its own.


## Steps

1. Recompile `ORDER001` with `ctl-opt dftactgrp(*no) actgrp('GCP');` instead of `actgrp(*caller)`.
2. Write a second small program `ORDERDET`, also with `actgrp('GCP')`, that is called by `ORDER001`.
3. Explain what `RCLACTGRP GCP` would do to both programs at once, compared to each program individually setting `*inlr = *on`.
4. Discuss the difference between `ACTGRP(*NEW)`, `ACTGRP(*CALLER)` and a named `ACTGRP('GCP')`.


## Solution

```
    CRTBNDRPG PGM(ORDER001) DFTACTGRP(*NO) ACTGRP('GCP')
    CRTBNDRPG PGM(ORDERDET) DFTACTGRP(*NO) ACTGRP('GCP')
```

```
   ctl-opt dftactgrp(*no) actgrp('GCP');
```

- `ACTGRP(*NEW)` creates a brand new activation group every time the program is called, and destroys it again when the program ends.
- `ACTGRP(*CALLER)` reuses whichever activation group called this program (or the default one, if called directly, e.g. from a command line).
- `ACTGRP('GCP')` is a specific, named activation group: both `ORDER001` and `ORDERDET` share it, and stay loaded together until explicitly reclaimed with `RCLACTGRP GCP`, or until sign-off.
- Compared to each program turning on `*inlr` individually (closing its own files, reinitializing its own variables), `RCLACTGRP GCP` reclaims everything in that named activation group at once, as one unit, without touching the rest of the job.
