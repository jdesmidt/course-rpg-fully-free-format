# 3.2.3 - Sending and receiving on a data queue

**Topics practiced:** `QSNDDTAQ`, `QRCVDTAQ`.

**Description:** send a short message onto a data queue, then receive it back, waiting up to 30 seconds if it is not there yet.


## Steps

1. Assume a data queue `MYQUEUE` already exists (created outside RPG with `CRTDTAQ DTAQ(MYLIB/MYQUEUE) MAXLEN(256)`).
2. Declare prototypes `sndDtaq` and `rcvDtaq`, with `extpgm('QSNDDTAQ')` and `extpgm('QRCVDTAQ')`.
3. Send the text `'Hello world'` (length 11) onto `MYQUEUE`.
4. Receive it back into a `char(256)` field, waiting up to 30 seconds, and display it.
5. Discuss what a `wait` value of `0` versus `-1` would mean instead.


## Solution

```
**free

dcl-pr sndDtaq extpgm('QSNDDTAQ');
   qname  char(10) const;
   qlib   char(10) const;
   dtaLen packed(5:0) const;
   dta    char(256) const;
end-pr;

dcl-pr rcvDtaq extpgm('QRCVDTAQ');
   qname  char(10) const;
   qlib   char(10) const;
   dtaLen packed(5:0) const;
   dta    char(256);
   wait   packed(5:0) const;
end-pr;

dcl-s wMessage char(256);

sndDtaq('MYQUEUE' : 'MYLIB' : 11 : 'Hello world');

rcvDtaq('MYQUEUE' : 'MYLIB' : 256 : wMessage : 30);   // wait up to 30 seconds
dsply wMessage;

*inlr = *on;
```

- `dtaLen` on `QSNDDTAQ` must match the actual length of the text being sent (`11` for `'Hello world'`), not the declared size of `dta`.
- `wait = 0` returns immediately, even if the queue is empty, `wait = -1` waits forever until a message arrives.
- A data queue holds plain data, not a described record format, this is why everything sent to it is built up as a character string (or a data structure), exactly like the C/IFS APIs earlier.
