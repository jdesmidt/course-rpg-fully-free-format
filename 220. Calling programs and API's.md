# Calling programs and API's

Sometimes the functionality you need already exists somewhere else: a program a colleague wrote, one of the many APIs IBM i ships with the operating system, a function from the C runtime library, or even a method written in Java. RPG can call all of these, in a very similar way.


## Calling programs (external)

### Prototyping

A prototype describes the interface of something external: its parameters, and its return value if it has one, so the compiler can check every call against it. It is declared with `dcl-pr`, followed by a name, and ends with `end-pr`, and must be known (coded, or `/copy`'d) before it is called for the first time.

```
   dcl-pr calcTax extpgm('CALCTAX');
      pAmount packed(7:2) const;
      pRate   packed(5:2) const;
      pTax    packed(9:2);
   end-pr;
```

`dcl-pr`/`end-pr` is the counterpart of `dcl-pi`/`end-pi` for a procedure (see the Internal procedures chapter): the same keywords `const`, `value` and `options(*nopass/*omit)` can be used on its parameters.

### EXTPGM

`extpgm('...')` tells the compiler that this prototype calls an external `*PGM` object, using the traditional `CALL` mechanism, not a bound procedure call. The literal between the parentheses is the actual object name in the library list, this way the RPG name used in your code (`calcTax`) can differ from the actual, at most 10 character, object name (`CALCTAX`).

Once prototyped, the program is called exactly like a procedure or a build-in function, no separate `CALL`/`PARM` operations are needed.

```
   dcl-s wTax packed(9:2);

   calcTax(100 : 21 : wTax);
   dsply wTax;
```

Unlike a procedure, a prototype for a program call has no return value: a program can only pass results back through its parameters (here `pTax`, passed by reference since it has no `const`/`value`).

### extproc

`extproc` is the counterpart of `extpgm`, but for a real procedure call instead of a `CALL`: a procedure exported by a service program (see the ILE concepts chapter), a function from the ILE C runtime library, or even a Java method (see further below). Because it is a real procedure call, it **can** have a return value, exactly like an internal procedure.

```
   dcl-pr sleep uns(10) extproc('sleep');
      seconds uns(10) value;
   end-pr;
```

### Incoming parameters

The called program itself (source member `CALCTAX`) declares the parameters it receives with `dcl-pi *n;` at the top level of its own source, exactly as covered in the Things to know about Free Format RPG chapter.

```
   **free
   dcl-pi *n;
      pAmount packed(7:2) const;
      pRate   packed(5:2) const;
      pTax    packed(9:2);
   end-pi;

   pTax = pAmount + (pAmount * pRate / 100);

   *inlr = *on;
```

The parameters on this `dcl-pi` must match the parameters of the `calcTax` prototype used by the caller: same number, same types, in the same order. The compiler cannot verify this by itself, since the two programs are compiled separately. A common way to keep them in sync is to put the prototype in its own source member and `/copy` it into both the caller and the called program.


## Executing commands from RPG

### QCMDEXC

Most of the thousands of APIs IBM i provides are just `*PGM` objects in library `QSYS`, they are prototyped and called exactly like `calcTax` above. `QCMDEXC` (Execute a Command) is a classic example, used to run a CL command from within RPG.

```
   dcl-s  command        varchar(256);
   dcl-s  commandlen     packed(15:5)

   dcl-pr ExecuteCommand extpgm('QCMDEXC');
      command char(3000) const;
      length  packed(15:5) const;
   end-pr;

   command = 'DLTF FILE(QTEMP/MYFILE)';
   commandlen = %len(%trim(command));

   ExecuteCommand ( command : commandlen );

   // or

   callp(e) ExecuteCommand ( command : commandlen );
```

The second parameter is the exact length of the command string that was passed, `26` in this example, the length of `'DLTF FILE(QTEMP/MYFILE)'`.


## System API's

Besides `*PGM` based APIs, IBM i also ships a whole C runtime library (accessible through `extproc`) and a set of "UNIX style" APIs to work with the IFS. Both are bound in with `bnddir('QC2LE')`.

```
   ctl-opt bnddir('QC2LE');
```

### Sleep

`sleep` pauses the job for a number of seconds.

```
   dcl-pr sleep uns(10) extproc('sleep');
      seconds uns(10) value;
   end-pr;
```

```
   sleep(5);                     // pause the job for 5 seconds
```

### IFS API's : opendir, readdir, closedir

These three C functions are used to list the contents of an IFS directory: `opendir` opens it and returns a handle, `readdir` returns the next entry (or `*null` when there are no more), `closedir` closes it again.

```
   dcl-pr opendir  pointer extproc('opendir');
      dirName pointer value options(*string);
   end-pr;

   dcl-pr readdir  pointer extproc('readdir');
      dirHandle pointer value;
   end-pr;

   dcl-pr closedir int(10) extproc('closedir');
      dirHandle pointer value;
   end-pr;
```

- `options(*string)` on `dirName` lets a normal RPG variable be passed as-is, RPG takes care of null-terminating it for the C function.

`readdir` returns a pointer to a `dirent` structure containing the file name (among other things). IBM documents its exact layout, most shops keep one ready-made template instead of retyping it by hand. Declaring it as a `template` data structure lets it be reused with `likeds`, `based` on the pointer `readdir` returns then lets that same layout be read directly from the memory it points to, exactly like the pointers/based fields covered in the Fields chapter.

```
   dcl-ds t_DirEntry qualified template;
      reserved1 char(16);
      reserved2 uns(10);
      fileno    uns(10);
      reclen    uns(10);
      reserved3 int(10);
      reserved4 char(8);
      nlsinfo   char(12);
      namelen   uns(10);
      name      char(640);
   end-ds;

   dcl-s  pDir      pointer;
   dcl-s  pEntry    pointer;
   dcl-ds fileEntry likeds(t_DirEntry) based(pEntry);
   dcl-s  fileName  varchar(128);

   pDir   = opendir('/home/jurgen');
   pEntry = readdir(pDir);

   dow pEntry <> *null;
      fileName = %str(%addr(fileEntry.name));      // read the null-terminated name as a varchar

      if fileName <> '.' and fileName <> '..';     // every directory also lists itself and its parent
         dsply fileName;
      endif;

      pEntry = readdir(pDir);
   enddo;

   closedir(pDir);
```

- `%str(address)` reads a null-terminated C string starting at `address`, and returns it as an RPG varying-length value, this is what turns `fileEntry.name` (a fixed `char(640)`, padded with whatever follows the actual name in memory) into a clean `fileName`.
- Every directory listing always includes an entry for itself (`.`) and its parent (`..`), these are normally filtered out by name, as shown above.

## Calling Java programs

ILE RPG can call Java methods directly, no separate RPG or C wrapper program is needed. This uses two dedicated features: the `object` data type, to hold a reference to a Java object, and `extproc(*java:...)`, to call a Java method or constructor.

### The object data type

```
   dcl-s obj_UUID   object(*java:'java.util.UUID');     // a Java object of type UUID
   dcl-s obj_String object(*java:'java.lang.String');   // a Java object of type String
```

- Declared with `object(*java:'fully.qualified.ClassName')`.
- It does not hold the object itself, only a reference to it, exactly like a variable in Java.

### Static methods

A static Java method is called the same way as any other prototyped call, its prototype needs the extra `static` keyword.

```
   dcl-pr randomUUID
      object(*java:'java.util.UUID')                   // return value
      static                                            // static method
      extproc(*java:'java.util.UUID':'randomUUID');     // java class/method
   end-pr;
```

```
   obj_UUID = randomUUID();
```

### Instance methods

For a non-static (instance) method, the object the method is called on is not declared as a parameter of the prototype, but is passed as the first argument at the call site.

```
   dcl-pr UUIDtoString
      object(*java:'java.lang.String')                 // return value
      extproc(*java:'java.util.UUID':'toString');       // java class/method
   end-pr;
```

```
   obj_String = UUIDtoString(obj_UUID);   // obj_UUID is the object toString() runs on, it is passed at the call, but never appears as a parameter above
```

### Constructors

`*constructor` calls a Java class's constructor, its return type is always the class being constructed. `like()` can be used to reuse the type of another field instead of repeating `object(*java:...)`.

```
   dcl-s JavaString object(*java:'java.lang.String');

   dcl-pr CreateString like(JavaString) extproc(*java:'java.lang.String':*constructor);
      text varchar(4096) const;
   end-pr;
```

```
   JavaString = CreateString('Hello world');
```

### Example: generating a PDF report with JasperReports

A real-world example, a small custom Java class `JasperToolbox` is used to compile, run and merge JasperReports (a popular Java reporting engine), all called directly from RPG.

```
   dcl-pr CompileReport int(10) extproc(*java:'JasperToolbox':'compileReport') static;
      jrxmlStringObj  object(*java:'java.lang.String') const;
      jasperStringObj object(*java:'java.lang.String') const;
   end-pr;

   dcl-pr GeneratePDF int(10) extproc(*java:'JasperToolbox':'generatePDF') static;
      jasperStringObj object(*java:'java.lang.String') const;
      outputStringObj object(*java:'java.lang.String') const;
   end-pr;

   dcl-pr MergePDF int(10) extproc(*java:'JasperToolbox':'mergePDF') static;
      finalStringObj object(*java:'java.lang.String') const;
      pdfsStringObj  object(*java:'java.lang.String') dim(10) const;
   end-pr;
```

- All three are static methods on the same class, so every parameter has to be declared explicitly, there is no implicit "this" object.
- `pdfsStringObj` is an array of Java `String` objects (`dim(10)`), used to pass a list of PDF file names to be merged into one.
