# Internal procedures

An internal procedure is a self-contained block of code, declared in the same source as the program that uses it. Unlike a subroutine, a procedure has its own parameters, its own local variables, and can optionally return a value. It is the modern, ILE replacement for subroutines.


## Advantages of using procedures

### DRY - Don't Repeat Yourself

- Avoid writing the same code twice.
- Once bullet-proof, it can be used as a black box.
- When a routine is re-used, there is only one place to make changes.

### KISS - Keep It Simple and Stupid

- Smaller pieces of code take less time to read and understand.
- Testing and debugging is easier when it's small.

### Compared to subroutines

| | Subroutine | Procedure |
| --- | --- | --- |
| Parameters | No, only works on global fields | Yes, its own parameter list |
| Local variables | No, shares all fields of the program | Yes, its own local variables |
| Return value | No | Yes, using `return` |
| Reusable in other programs | No, always local to one program | Yes, when placed in a service program |
| Declared with | `begsr` / `endsr` | `dcl-proc` / `end-proc` |

Because a subroutine has no parameters, every value it needs has to be put into a global field before each call, which is repetitive and error-prone. A procedure receives its input as parameters, so the call site stays short and every call can use different values.

```
   // subroutine: globals need to be set before every call
   wPrice = 10; 
   wQty = 3;
   exsr calcTotal;
   dsply wTotal;

   wPrice = 25; 
   wQty = 2;
   exsr calcTotal;
   dsply wTotal;

   begsr calcTotal;
      wTotal = wPrice * wQty;
   endsr;
```

```
   // procedure: values are simply passed as parameters
   dsply calcTotal(10 : 3);
   dsply calcTotal(25 : 2);

   dcl-proc calcTotal;
      dcl-pi calcTotal packed(9:2);
         pPrice packed(7:2) const;
         pQty   int(5)      const;
      end-pi;

      return pPrice * pQty;
   end-proc;
```


## Default activation group can not be used

Procedures are an ILE concept, a program that uses them cannot run in the default (OPM) activation group. As covered in the Control statements chapter, every source that uses procedures needs:

```
   ctl-opt dftactgrp(*no) actgrp(*caller);
```


## Procedure declaration 

A procedure is declared with `dcl-proc`, followed by a name, and ends with `end-proc`. Everything between them, parameters, local variables and calculations, belongs to that procedure only.

```
   dcl-proc calcTotal;
      // dcl-pi, local variables and calculations go here
   end-proc;
```

### Procedure interface : incoming and outgoing parameters

`dcl-pi` defines the procedure interface: its parameters and, optionally, its return type.

When `dcl-pi` uses the exact same name as the enclosing `dcl-proc`, no separate prototype is needed, this is the simplest way to declare an internal procedure.

```
   dcl-proc calcTotal;
      dcl-pi calcTotal packed(9:2);
         pPrice packed(7:2) const;
         pQty   int(5)      const;
      end-pi;

      return pPrice * pQty;
   end-proc;
```

Inside a `dcl-proc`, the name on `dcl-pi` is only there to match it up with a prototype, since an internal procedure normally has none, the name can simply be replaced by `*n`. This is exactly what the main procedure example further below does.

```
   dcl-proc calcTotal;
      dcl-pi *n packed(9:2);
         pPrice packed(7:2) const;
         pQty   int(5)      const;
      end-pi;

      return pPrice * pQty;
   end-proc;
```

- The type right after the procedure name (here `packed(9:2)`) is the return type. Leave it out when the procedure does not return a value.
- By default a parameter is both incoming and outgoing (passed by reference): the procedure can change the caller's variable through it, unless `const` or `value` is used (see below).

### Return values

`return` ends the procedure immediately. If `dcl-pi` declares a return type, `return` must be followed by a matching value. If `dcl-pi` has no return type, use `return;` on its own to exit the procedure early, without a value.

```
   dcl-proc isPositive;
      dcl-pi isPositive ind;
         pAmount packed(7:2) const;
      end-pi;

      return pAmount > 0;
   end-proc;
```

```
   test =  isPositive(-5);          // *off
   test =  isPositive(5);           // *on
```


## Keywords value/const

- No keyword (default): passed by reference. The caller's own variable is passed, changes inside the procedure change the caller's field too. Only a variable can be passed this way, not a literal or an expression.
- `value`: passed by value. The procedure receives a private copy, changes have no effect on the caller. A literal or an expression can be passed.
- `const`: passed by reference, but read-only, the procedure cannot change it. A literal, an expression, or a variable of a different (but compatible) type or length can be passed, the compiler creates a temporary copy whenever needed.

```
   dcl-proc addTax;
      dcl-pi addTax packed(9:2);
         pAmount packed(7:2) value;
         pRate   packed(5:2) const;
      end-pi;

      return pAmount + (pAmount * pRate / 100);
   end-proc;
```

```
   total = addTax(100 : 21);        // literals are allowed thanks to value/const
```

`const` is the most commonly used keyword for parameters that are only read by the procedure, it is both safe and flexible.


## Keywords options(*nopass/*omit)

- `options(*nopass)` makes a parameter optional, the caller may leave it out (only the last parameters of the list can be optional).
- `options(*omit)` allows the caller to explicitly pass `*omit` instead of a real value.

### Checking number of parameters

`%parms` and `%parmnum` were already introduced in the Built-in functions chapter. Combined with `options(*nopass)`, they are the standard way to check whether an optional parameter was actually passed.

```
   dcl-proc calcDiscount;
      dcl-pi calcDiscount packed(7:2);
         pAmount packed(7:2) const;
         pRate   packed(5:2) const options(*nopass);
      end-pi;

      if %parms < %parmnum(pRate);
         return pAmount;                 // pRate was not passed
      endif;

      return pAmount - (pAmount * pRate / 100);
   end-proc;
```

```
   dsply calcDiscount(100);        // 100.00, no discount
   dsply calcDiscount(100 : 10);   // 90.00
```

A newer, simpler alternative is `%passed(parameter)`, it directly returns `*on` when the parameter was passed (and not omitted). This avoids having to compare `%parms` to `%parmnum`. It requires IBM i 7.4 (via PTF) or later.

```
   dcl-proc calcDiscount;
      dcl-pi calcDiscount packed(7:2);
         pAmount packed(7:2) const;
         pRate   packed(5:2) const options(*nopass);
      end-pi;

      if not %passed(pRate);
         return pAmount;                 // pRate was not passed
      endif;

      return pAmount - (pAmount * pRate / 100);
   end-proc;
```

### Checking if parameter is *omitted

When the caller passes `*omit` for an `options(*omit)` parameter, the address of that parameter becomes `*null`. Check this with `%addr(parameter) = *null`.

```
   dcl-proc showMessage;
      dcl-pi showMessage;
         pText   varchar(50) const;
         pPrefix varchar(10) const options(*nopass : *omit);
      end-pi;

      if %addr(pPrefix) = *null;
         dsply pText;
      else;
         dsply (pPrefix + ': ' + pText);
      endif;
   end-proc;
```

```
   showMessage('Done');                  // 'Done'
   showMessage('Done' : 'INFO');         // 'INFO: Done'
   showMessage('Done' : *omit);          // 'Done', explicitly no prefix
```

- `options(*omit)` on its own only allows the caller to explicitly pass `*omit` instead of a real value, it does not make the argument optional to leave out of the call entirely, that still needs `options(*nopass)` too. `pPrefix` above combines both, which is why all three calls (no second argument at all, a real value, and explicitly `*omit`) are valid.

The newer alternative here is `%omitted(parameter)`, it directly returns `*on` when `*omit` was passed for that parameter, without needing `%addr`. Just like `%passed`, it requires IBM i 7.4 (via PTF) or later.

```
   dcl-proc showMessage;
      dcl-pi showMessage;
         pText   varchar(50) const;
         pPrefix varchar(10) const options(*nopass : *omit);
      end-pi;

      if %omitted(pPrefix);
         dsply pText;
      else;
         dsply (pPrefix + ': ' + pText);
      endif;
   end-proc;
```

- `%passed` and `%omitted` are also commonly combined, `%passed` tells you whether an argument was supplied at all, `%omitted` tells you whether it was explicitly `*omit`.

### Other options: *trim / *rightadj

These two extra `options()` values control how a `const` (or `value`) character parameter is copied into its temporary variable when the actual argument's length does not match the declared one:

- `*trim` removes leading and trailing blanks from the passed value before it is copied.
- `*rightadj` right-adjusts the value into the parameter (pads with blanks on the left) instead of the default left-adjust.

```
   dcl-proc formatCode;
      dcl-pi formatCode varchar(10);
         pCode char(10) const options(*trim : *rightadj);
      end-pi;

      return pCode;
   end-proc;
```

```
   dsply formatCode('AB');        // '        AB', trimmed, then right-adjusted into 10 positions
```


## on-exit

`on-exit` defines a block of code inside a procedure that always runs when the procedure ends, no matter how it ends (a `return` anywhere in the procedure, or even an error), comparable to a "finally" block in other languages. It is useful for cleanup, like releasing allocated memory. This requires at least IBM i 7.2 TR5 / 7.3 TR1.

```
   dcl-proc readFile;
      dcl-pi readFile ind;
      end-pi;

      dcl-s wPtr pointer;

      wPtr = %alloc(100);

      // ... use wPtr ...

      return *on;

      on-exit;
         dealloc wPtr;             // always runs, even after the return above
   end-proc;
```

## Replacing the main program by a main procedure

Normally, the "loose" calculation statements at the top level of a source (outside any `dcl-proc`) form the program's entry point, tied to the old RPG cycle. `ctl-opt main(procedure-name)` designates a procedure as the actual entry point instead: the program starts there directly, and that procedure gets all the benefits of a normal procedure (its own local variables, being callable recursively, ...).

```
   ctl-opt main(main);

   dcl-proc main;
      dcl-pi *n;
         pRtcd char(1);
      end-pi;

      // this now runs first, instead of loose calculation statements
      dsply 'Hello world';
   end-proc;
```

- The parameters of the main procedure become the parameters of the program itself.
- The RPG cycle is not just started differently, it is bypassed entirely: `*inlr` is not used, and does not need to be set. The program simply ends when `main` does a `return` (or falls off its own end), exactly like any other procedure.
- Because there is no cycle, there is also no automatic cleanup: any file left open, or data area left locked, stays that way when the program ends, unless it is closed/unlocked explicitly (an `on-exit`, see above, is a natural place for that).
