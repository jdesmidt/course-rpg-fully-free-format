# Data areas and SQL sequences

## Data areas

A data area (`*DTAARA`) is a small, simple object that stores one value outside of any program. It is useful to share a value between jobs, or to keep a value across program calls, without needing a database file. The Local Data Area (LDA), covered in the Data structures chapter, is one special, always-available data area, this chapter covers user-created, named data areas.

### DTAARA / IN / OUT

A field (or data structure) is linked to a data area with the `dtaara('name')` keyword. `in` reads the current value into the field, `out` writes the field's value back to the data area.

```
   dcl-s sequence zoned(9) dtaara('COUNTER');

   in *lock sequence;      // read the value, and lock the data area for update
   sequence += 1;
   out sequence;           // write the new value back, and release the lock
```

- `dtaara('COUNTER')` links the field to an existing data area named `COUNTER` (found through the library list), instead of the special value `*lda` used for the Local Data Area.
- `in` alone just rereads the current value. Adding `*lock` also locks the data area exclusively, so no other job can read it with `*lock`, or update it, until it is unlocked again.
- `out` writes the field back to the data area, and releases a lock taken with `in *lock`.
- `unlock` releases a lock without writing a value back, for when the update turns out not to be needed after all.

```
   in *lock sequence;

   if sequence >= 999999999;
      unlock sequence;             // give up the lock, change nothing
   else;
      sequence += 1;
      out sequence;
   endif;
```

- The data area itself is created once, outside RPG, with the CL command `CRTDTAARA`, this chapter only covers using an existing one from RPG.
- This lock/read/update/write pattern is a simple way to hand out a unique sequence number even when several jobs run the same program at the same time, without needing a keyed database file for it.


## LDA (Local Data Area)

The Local Data Area is a small storage area of 1024 bytes, automatically available to a job. It can be used to pass a small amount of data between programs that run in the same job, without using parameters.

A data structure is linked to the LDA with the `dtaara(*lda)` keyword. `in` reads the current content of the LDA into the data structure, `out` writes the data structure back to the LDA.

```
   dcl-ds wLda dtaara(*lda);
      wUserId char(10) pos(1);
      wLastRun date(*iso) pos(11);
   end-ds;

   in wLda;                      // read the LDA
   dsply wUserId;

   wLastRun = %date();
   out wLda;                     // write the changes back to the LDA
```

- Only the part of the LDA that is actually needed has to be declared, using `pos` to match the correct positions.
- The LDA is job-wide: every program in the call stack of the same job sees the same content.


## Sequences

An SQL sequence is a database object that also generates unique numbers, an alternative to the data area technique above, and to an identity column (see the Embedded SQL chapter).

```
   dcl-s sequenceNumber zoned(8);

   exec sql
      select next value for order_sequence
        into :sequenceNumber
        from sysibm.sysdummy1;
```

- A sequence is created once, outside RPG (`create sequence order_sequence ...`). Unlike an identity column, it is not tied to one particular table, several tables (or a program, like above) can share the same sequence.
- `next value for sequence-name` returns the next number and reserves it immediately, even if the current transaction is later rolled back that number is not reused, so gaps in the sequence are normal.
- `sysibm.sysdummy1` is needed here for the same reason as with `identity_val_local()`: `select` requires a `from`, even though the value does not come from a real table.

A sequence number like this is often combined into a single code together with part of the current date:

```
   return %char(%subdt(%date():*years)) + %editc(sequenceNumber:'X');
```

- `%subdt(value:unit)` extracts one part of a date, time or timestamp, here `*years` extracts just the current year.
- `%editc(sequenceNumber:'X')` formats the sequence number while keeping its leading zeros, edit code `X` is the one edit code that does not suppress them (unlike the codes covered in the Built-in functions chapter).
- Together this builds one code, for example `'2026000123'`: the current year followed by the zero-padded sequence number.
